# 長押し移動の停止判定と止め直し（#115）

2026-11-03 JST。はねさんの「新しいダメージモーションも含めて遊びやすく、長押しストップの引っ掛かりを滑らかに」の採用依頼。[Issue #115](https://github.com/hane-san/SRPG-01-FEstyle/issues/115)に実装前設計。起点mainは `d4c0274`（#114統合後）。危険度high：指の保持/固定/訂正/取消と命令確定の境界を横断する。

## 原因と変更

- 旧判定は指の座標を見ず、「同じマスに200ms」で固定していた。拡大した1マスの中をゆっくり滑らせていても固定され、別の空きマスで止め直しても最初の行き先が残る。変更前の実ポインタ操作で両方を再現した。
- 保持タイマーに座標を渡し、6 CSS pxを超える移動で200msを数え直す。6px内の小さな手振れは許容。固定済みの射撃地点は、その後の指移動だけでは解除しない。
- 同じドラッグ内で自動固定した移動先は、別の合法な空きマスで再び200ms止めると固定し直せる。途中で通過するだけなら古い射撃地点を維持し、別の空きマスですぐ離す場合は従来どおり取消。以前に描いた明示的な経路を別の指操作で継続する場合は、その経路を保持する。
- 止め直し候補の占有/合法経路を既存engineで検査し、固定後の行き先・経路・表示を揃える。取消・二本指・画面離脱は旧ドラフトへ戻し、命令/消費/保存を発生させない。移動確定は指を離した時だけ。移動後Undoを保持する。
- 世代番号でタイマーを無効化する。同じセルへ戻った場合でも、既に配送待ちになった古いコールバックが新しい保持を早く固定しない。
- ドラフトは各入力で同期更新し、表示だけrequestAnimationFrameでまとめる。同一セルの動きは停止判定のみ更新し、経路を再探索しない。確定/取消では表示予約と両保持タイマーを清掃する。指示点や敵の通過を描画間引きで飛ばさない。

engine/数値/AI/マップ/保存形式・キー/兵種/音楽/カメラ/表示名/定期設定の変更なし。HP6、P1→P4、出撃2/1/5、静止P3、144pxドック（横持ちは300px列）と44px操作対象を維持。本編の直接移動オプションの既定値も変更しない。

## 検証

- 変更前のブラウザ再現：同一セルを滑り続けても固定される=true、別セルで停止後も旧dest=(4,15)。変更後：滑走中の固定=false、停止して修正したdest=(3,15)。保持中のcommands=0、pageerror=0。
- Node：セル内の滑走/停止/小さな指ぶれ、同じセルへ再入場した後の古いcallback、別セルでの再保持と取消を追加。既存保持・タップ・取消の検証も保持する。
- 追加ブラウザ：320/360/390縦・844横で拡大セル内の滑走→停止→確定、止め直し→1命令、Undo、pointercancel/二本指/blur中断、保存不変、カメラ安定。01/04×両3Dの実WebGLセッションでは出撃→敵フェーズ→止め直し移動→次命令まで確認する。
- 既存quick-flickで、射撃地点を保つ遠距離攻撃、200ms未満の敵フリック、別空きマスの即離し取消、P3職の誤攻撃なし、出撃・Undoを確認。
- `npm run check`と`npm run test:browser`に追加テストを含める。#114の半片演出とP3表示検証を削らない。最終SHA・CI・main/Pagesと公開内容の検証結果はPRへ記録。
- ルール/数値/マップは変更しないためsimulateは対象外。独立監査、iPhone/WebKit実機、実耳、手触り・難度・美術の人間評価は未検証。

## 試遊

全幅と拡大で「ゆっくり滑らせる→止める→別の空きマスで止め直す→離す」を試す。固定後も敵へ素早く滑らせれば、その射撃地点から攻撃できることを比べる。別の空きマスで止め直す前に離すと取消になる。攻撃後の最新HP/撃破演出を見てから、次の部隊を続けて選べるか確認する。
