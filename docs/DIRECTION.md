# 英雄叙事詩 — シナリオと戦場設計の方向性

> 更新：2026-10-22。**決定済みの物語原則**、**今回採用されたマップ設計の方針**、**提案・未採用**、**未検証**を明確に区別する。台詞・国家・宗教・人物名など未決定の世界設定を確定したものとして扱わない。
>
> シナリオ方向性の集約先は本書。現在の戦闘ルールは [hp6-campaign-design.md](hp6-campaign-design.md)、採否履歴は [DECISIONS.md](DECISIONS.md)、マップ改修は [Issue #38](https://github.com/hane-san/SRPG-01-FEstyle/issues/38) を参照。相互矛盾があれば現行 `main`・テスト・Issueを照合してから決裁する。

## 1. 決定済みの物語原則（既存資料の再整理、今夜の新規シナリオ決裁ではない）

- **軍事合理性が感情を動かす。** 主人公のそばにいる将軍は、味方が倒れても通常戦線へ出ない。全体の戦況を把握し、本城で作戦を支える方が合理的だから。最終章では逆に本城防衛のため出撃することが合理的になる。
- **将軍の最期は変えない。** 最終的に討死／殉死する決意と人格を守り、安易な生存エンディングは作らない。ただし将軍がゲーム内で倒れる場合と、主力が早くラスボスを倒して将軍が決着に合流できる場合とで、場面・対話・回想・救えた命・真相の厚みを意味ある形で変える。プレイヤーの努力を否定する強制イベントにしない。
- **本城側の敵にも理由がある。** 過去に倒した名ヴィランを慕う残党の反攻には忠誠と行動理由がある。将来の敵は「何のためにそこにいるか」を地形・配置・行動に反映したい。
- **ネームドの喪失は人格の喪失。** クラシックでは本人は戻らないが、同兵種・同ランクの一般兵が次章の編成枠を補う。基本戦力が不足して主筋攻略不能となる設計は避ける。一般兵は固有技能・本人の人間関係・会話を代替しない。
- **上手いプレイヤーは物語の深さを得る。** 重要な結末と本筋の理解は誰にも届く。生存、戦術的な選択、隠れた目標、外伝・回想によって「知ることのできる真実」が深まる。完走に特定のネームド・外伝を強制しない。
- 具体的な最終章のイベント順、主人公・将軍・敵将の名前、独立した分岐エンディング、世界観の様式と政治宗教史、台本は**保留・未実装**。

### 戦闘システム上の確定条件（改修で壊さない）

- HP6固定、命中・必殺乱数なし、通常下級攻撃2、重装は固有軽減、4フェーズ（P1味方／P2敵／P3静止専門支援／P4予告済みイベント）。
- 全味方が本城内の予備から開始。最初のP1は2隊、その後は各ターン1隊出撃、盤面最大5隊。出撃前の敵からの攻撃対象にはしない。
- P3は静止待機した砲兵の砲撃と魔術師系の治療のみ。移動後P3なし。城周囲の弾薬補給、反撃の放棄を維持。
- 01〜03は連戦、04〜06は単体試験マップ。現在は単一目標城制圧が主、02は本陣陥落で敗北。**未実装の副目標や会話フラグを、実装済みの遊びとして案内しない。**

## 2. 採用されたマップ・バランス設計原則（今回の依頼）

**プレイヤーの一手が、後のドラマと同じ因果で動く戦場を作る。** 地形、敵、通路、橋、拠点、寸法は面白くなるなら大胆に変更してよい。既存の橋の本数や地図構造は不可侵ではない。

1. **「待機」を退屈ではなく戦略にする。** 盾で城を守る、砲兵・魔術師を有効な場所へ据える、補給のため後ろに残す。02は本城防衛と攻勢の代償を最初に検証する舞台。
2. **「前進」を無意味なターン消費にしない。** 01では多少雑な行動でも十分進め、巧い人は停止せず連続攻撃・速攻できる。03/06では迅速突破の利益と、砲撃・増援の危険を両立する。全マップ共通の強制タイムリミットは導入しない。
3. **二正面の原型を育てる。** 守る・攻める・迂回する・予備を投入する意味を02/04/06で試し、最終章に必要な戦線分割方式は試遊後に選ぶ。
4. **犠牲が「気付けたのに防げなかった」結果となるようにする。** 危険の予告、敵の意図、反撃・HP6、逃げ道を読めることが原則。クラシック初見で不可避の名有り死亡を安易に強制しない。
5. **兵種の物語的役割は地形に宿す。** 騎兵なら間に合う、盾なら道を守れる、弓なら橋の向こうへ手を出せる、静止砲撃・回復なら戦線を支えられる。特定ネームド専用の必須解法は避ける。
6. **戦闘の質を比較する。** 勝った/負けた以外に、初交戦・無交戦ターン・戦力配分・城の存続・犠牲・手数・高速進軍の差・P3発動・iPhone操作量を検証する。単一方策の勝利は「面白さ」の証明ではない。

## 3. 今夜実装・整備してよいもの（限定）

- **今すぐ**：この資料を `docs/DIRECTION.md` に置く。マップ Issue #38 と紐づけ、確定/提案/未検証を分ける。設計資料のみのPRでよい（[Issue #40](https://github.com/hane-san/SRPG-01-FEstyle/issues/40)）。
- **今夜の優先候補**：既存の observer / metrics / simulation から取れる範囲で比較レポート・テストを整え、01の快走感と02/06の本城防衛を検証する。新規セーブ形式や戦闘ルールには触れない（[Issue #41](https://github.com/hane-san/SRPG-01-FEstyle/issues/41)）。
- **マップ改修**：01の比較可能な試作を最優先し、02〜03、04〜06と順に再構成する。寸法・橋・森・城・敵は変えてよいが、P1出撃・P3・予告・既存セーブへの影響を検証する（[Issue #38](https://github.com/hane-san/SRPG-01-FEstyle/issues/38)）。
- T1二隊出撃後の読込上限不整合は [Issue #37](https://github.com/hane-san/SRPG-01-FEstyle/issues/37) で別途検証。保存の破壊や互換性軽視をマップ改修の副作用にしない。

## 4. 物語とシステムを結ぶ選択肢（A・Bは2026-10-22に採用）

### A — 最終章の二正面の表現方法（2026-10-22採用、設計を決定）

[Issue #42](https://github.com/hane-san/SRPG-01-FEstyle/issues/42)：**単一盤面の同時二正面**、**本城側だけ局所的に戦況を解決**、**章内二戦闘を連動**の3方式を比較する。最終章の将軍・本城に残した部隊・主力の速攻・残党の攻勢へ、どれが最も因果と操作を両立できるかを試遊で決める。盤面最大5隊・縦スマホ・予告済みP4と衝突しないかが重要。

**採用（2026-10-22、はねさん）と比較の結論**

| 観点 | 単一盤面の同時二正面 | 本城側だけ局所解決 | 章内二戦闘の連動 |
|---|---|---|---|
| 縦スマホでの見通し | ×（盤面が長く両方を同時に見られない） | ○ | ○ |
| 盤面最大5隊・出撃枠との両立 | ×（分兵すると両方が薄い） | △（守備隊の数をどう効かせるかが新ルール） | ○（各戦闘で5隊） |
| 因果の分かりやすさ | ○ | △（見えない場所で決まる） | ○（前半の結果が後半の盤面に出る） |
| 同時進行の緊張感 | ○ | ○ | △ |
| 実装の重さ・保存 | 大（新勝利条件・長大マップ） | 中（新しい戦況ゲージ） | 小〜中（既存の章間持ち越し＋戦果記録を流用） |

**試作は「章内二戦闘の連動」から**：本城防衛戦（短い盤面、将軍は動かない拠点として存在）→ 主戦場。前半で守り切った本陣の状態と残した部隊が、後半の開始条件と戦果記録に反映される。同時進行感の弱さは、後半開始時の短い報告と予告済みP4で補う。#38の02（本城を守る）・06（長期戦）の試遊結果を見てから、この案専用の実装Issueを作る（盤面・勝敗条件・保存移行・テスト付き）。

**引き続き入れないもの**：将軍の恒常プレイアブル化、無限増援、見えない戦況ゲージ、汎用の多戦域エンジン。

### B — 戦果とシナリオ分岐を結ぶ小さな記録（2026-10-22採用、第一段階は実装済み）

[Issue #43](https://github.com/hane-san/SRPG-01-FEstyle/issues/43)：早期突破、守った拠点、名前のある者の生存/喪失、副次的な救出や対話などから、結末ではなく回想・会話・理解の深度を変える。後に採用するなら、**観測した事実** → **章末確定の戦果** → **物語条件** を分離する。

- 現在の `engine.js` はターン・死亡等を保持するが、章間に伝える進行情報は主に `lost`/`specialties`。シナリオ条件の永続記録は未実装。
- 新しい話の条件フラグ、セーブ migration、勝利条件、イベント API は一度に作らず、採用された具体例から最小限で設計する。
- **第一段階（実装済み）**：`chronicle.js` が章末に「制圧ターン・命令数・離脱数・帰らなかった名のある隊長・南城を先に取ったか」を記録し、連戦で持ち越して結果画面の「戦果記録」で振り返れる。結末・難易度・会話は変えない。旧保存は空の記録で読み込む。次の段階で、この記録を回想や会話の厚みに使う。
- 村・橋・砦・守護者・敵伝令・避難路・名ヴィランの残党などは**素材候補**にすぎない。今のタイル `v`（村）に救出処理はない。敵への説得・降伏、外伝を自動導入しない。

### 提案C — 物語と結びつくマップ固有の雰囲気

橋一本に敵が固執する理由、住民のいる村を避ける攻勢、雨期の遅い救援、見えるのに届かない友軍、撤退を選ばない残党など、**ユニットの目標や地形から物語が伝わる**要素は有望。ただし民族・国家・宗教・敵の政治的正当性など、世界観の大枠は別途プロデューサーが決める。

## 5. 検証と引継ぎ

- `npm run check`、地形/数値変更時 `npm run simulate`、入力や盤面変更時 `npm run test:browser`、PRの `rules`/`browser` CI結果を記録する。旧Issue #17の調整値は当時の固定方策による歴史的な比較値であり、新しい出撃ルールの現在値ではない。
- 特にシナリオ効果の予想はゲームの実測ではない。「戦闘として成立」「技術的に安全」「人間が楽しい」の3つを混同しない。iPhone実機は人間の試遊まで未検証。
- PR #36（フリック攻撃と宝石の破砕音）、Issue #39（エフェクト）など進行中の別作業を巻き戻さない。文書のPRはゲームロジックや保存キーを変えない。
- 夜間Codexが方向性をPRとして整理し、翌15時Claude昼ランが競合・CI・採否を総合して扱う。提案節から勝手に実装Issueを起こしたり、mainへ直接push・GitHub auto-mergeしたりしない。


## 2026-10-25 採用：工業幻想の見た目試遊（Issue #76）

**採用済みなのは「別モードとして外縁工業地帯（01）と三橋水路戦（04）の見た目を試す」ことのみ。** 作品全体の世界観、国家設定、主人公、社会哲学は引き続き提案・未決定であり、本編へはまだ反映しない。

- 通常ゲームはそのまま。`?sample=01` と `?sample=04` は既存マップの地形・部隊・勝敗条件・AI・数値を共有し、装飾と表示名だけを変える独立の非保存セッション。
- 試遊セッションでは通常の `field-command-save-v1` を読まず、書かない。メニューの「本編へ戻る」で元の進行に戻れる。更新すると試遊は初期状態に戻る。
- 試作の意匠は煤けた工業都市、真鍮配管、運河、琥珀の作業灯、工場護岸、巨大制御門。04は橋ごとに異なる床意匠。あくまで32px俯瞰戦術表示の独自タイル絵であり、生成した斜め投影のコンセプトラフをそのまま地形データとして扱わない。
- **採用判断は実際のスマートフォン試遊後。** アート密度、ルートの見やすさ、01の快走感、04の橋の読みやすさを比べる。新兵種、潜入、機甲換装、P4新規効果などのシステム提案とは切り離す。
- mainへ直接pushや自動マージはしない。CIと必要な監査を経て、利用可能な公開版で試す。未検証事項を完成扱いしない。

## 2026-10-31追記：出撃と操作文法の統一（#96）
出撃セリフはいったん撤去し、予備の選択から通常の移動・攻撃へ自然に繋ぐ。味方魔術師はP1攻撃不可の回復特化として表示し、静止P3と移動待機を読み分けられるUIへ。スライド/待機/ターン終了の一貫性を優先して比較試作する。これは出撃字幕を要求した過去仕様を上書きする最新判断。HP6・P3静止・回復量/対象・出撃枠・保存は維持。[UI実装仕様](interaction-consistency-96.md)。


## 2026-10-31追記：2/3案の美術品質を引き上げる（#97）
2スチームパンク・3写実寄りファンタジーは、現状の簡素な仮描画から、GBA以上を目標とする造形/材質/陰影/動きを持つ美術へ進める。色替え・描画解像度だけで完了にせず、普段の全幅画面でも地形と駒の違いが明確に見えることを受入にする。1現行と同一戦況/カメラの切替を維持。[詳細仕様](art-quality-97.md)。今回は美術実装の準備で、品質達成/本編世界観採用は未確定。
