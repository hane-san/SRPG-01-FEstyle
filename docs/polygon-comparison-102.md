# 3案比較を「現行2D＋2つのポリゴン3D」へ更新（2026-11-02）
## 最新の依頼と採否
プロデューサー：追加2つはさらに精細で個性的に、ゲームボーイ風ドットより上へ。ポリゴンの3D風表現を検討し、小ささはサイズ調整で解決。他の本人の3Dゲームも参考にし、最初版と合わせ3つを比較したい。
本書では1現行2D／2スチームパンク3D／3写実寄りファンタジー3Dとして具体化する。比較対象を4つに増やさない。#97の2/3を高密度pixel artだけで作る案を更新し、実ポリゴンの立体描画を第一候補とする。2Dを斜め変形するだけの疑似3Dでは完了としない。写真風/自由探索/3D戦闘ルールの導入は求めない。今回は設計準備、追加3D版は未実装。

## 読んだ参考と転用の限界
- hane-san/ARPG-01-SkyrimStyle：README.md、dist/island.js（2026-11-02取得）。WebGLで位置/法線/頂点色を持つ三角形、面の光と霧、バッファ単位の描画・地域の省略、端末pixel ratio上限、手続き造形と水面を確認。SRPGへは立体造形・限定した陰影・共有モデル・描画負荷制御の考え方を使う。一人称カメラ/移動/衝突は移植しない。
- hane-san/cyber-punk：README.md、game/js/main.jsを参照。three.js r128をCDN読込する別構成と、斬撃中にカメラ方向を急変させない処理を確認。材質/都市のスケール差の参考にし、CDN依存や速度連動カメラをSRPGへ持ち込まない。
他repoは参照のみ、変更しない。ライブラリ/素材を実際に再利用するならライセンスと依存を確認。SRPGの外部CDNなしの契約は維持し、まず凪の島のような小さなWebGL実装を評価する。特定技術の現在仕様は実装時に確認。

## カメラと小ささへの対策
- 第一候補は正投影・北を画面上に固定したやや見下ろしの視点。真上から少しだけ傾け、正面と側面を読ませる。奥ほど駒が小さくなる強い透視や、45度回転を必須にしない。
- 駒は完全写実の縮尺へ拘らず、頭/盾/武器/馬と足元を読みやすく誇張。駒の画面上の大きさ、見える列数、遮蔽を同時に測る。提案の開始目安は通常の戦術表示で駒の高さ26〜36 CSS px程度。これを保証値にせず320px縦で複数部隊を見渡せる範囲に調整する。
- 低倍率でも兵種/所属/行動済/HPが読める共通オーバーレイ。指で触れる領域は見た目と整合した候補選択を設け、狭い盤面で44px領域を単純に重ねて別の敵を選ばない。
- 戦術表示と全景を明示操作で切替できる候補。指保持/選択/攻撃/予告で勝手にズーム/回転/パンしない。既存固定dockの寸法は維持。
- 手前の城壁/樹冠は必要時に透過/上部省略。足元・経路・HPが隠れない。大きなHP表示とP2の間は最新#101へ合わせ、頭上表示が木や建築に埋まらないよう画面座標へ投影する。

## ゲームモデルは2Dグリッドのまま
engineの同じstate/命令/経路/地形コスト/AI/勝敗/P1〜P4/HP6を共有し、3Dは描画アダプタのみ。絵の段差を移動コスト/高低差ボーナスへ変えない。既存セーブの座標/形式/キーを変更しない。
Canvas2DのclientX÷tile判定を3D画面へ流用しない。共通のscreenToCell/cellToScreenと、カメラ行列・地面との交差を使う指示点変換を設計する。飾りのメッシュを選んでも地面上の正しいセル/駒に対応すること。橋/地形の表示高さも一意に扱い、見た目の投影と当たり判定を一致させる。
レンダラ切替は同じ中心セル/選択/ドラフト/戦況を維持。投影が違う2D/3D間でscrollLeftの数値一致は要求せず、中心セルと画面上の意図が保持されることを検査。3D2案の間は同じ投影/カメラを使い、造形だけ比較する。指保持/演出中の切替は拒否または安全に解除してから実行。GPUに失敗したら2Dへ明示復帰しゲーム/セーブを失わない。

## 実装順と検証
1. 描画/入力座標変換の技術設計。グリッド、選択、移動、HP、同一状態の切替から。
2. 01の橋・城・森と重装/騎兵/回復職を含む同じ代表場面を、2/3とも完成密度で可遊化。原始形状だけの技術デモと美術完成を区別する。
3. 01/04を最後まで遊べる全地形/全兵種/両陣営/行動済へ拡張。#92比較基盤/#96操作統一/#101表示順と共用。音・AIは比較中固定。
4. 各案の初期描画時間、フレーム時間、draw calls/三角形数、GPUリソースとメモリ見積を記録。再切替でモデル/バッファを増殖させない。WebGL context lost/restored・背景復帰・回転に対処。影の品質/DPR/効果量の軽量設定を検証。WebGLのない環境は明示2D復帰。実機での60fps等は計測前に保証しない。
5. 320/360/390px縦・844横、画面端/遠近/遮蔽/密集で、駒選択・敵フリック・出撃・静止治療・予告・ターン終了。screen→cell→screenと2D/3Dで同じ命令列の最終状態一致、本編保存不変をテスト。旧Canvasの二層32pxキャッシュ契約は2Dで維持、3DのGPU資源上限は設計して別記する。
6. 同戦況/同じ中心/3D同士同倍率で3案の画像と可遊比較。人間の「細かく個性がある/小さくない/狙いやすい」を評価。自動pixel差分/CIだけでGBA以上の美術を達成としない。iPhone Safari実機・聴感・美術評価・独立監査は未検証なら明記。
リスクhigh（描画経路と座標変換）。engineを複製せず設計→小PR→CI/必要な監査。main直push/自動mergeなし。本編の3D化決定ではなく独立テスト比較。
